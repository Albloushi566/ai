\# AI Prompt Engineering Cheat Sheet



Prompt engineering is the practice of structuring text input so that an AI model produces the most accurate and useful output.



\---



\## 1. Core Framework (R-T-C-O)

When writing a prompt, define these four components:

1\. \*\*Role:\*\* Who is the AI acting as? \*(e.g., "Act as a senior DevOps engineer")\*

2\. \*\*Task:\*\* What exact action should it take? \*(e.g., "Review this SQL query for performance bottlenecks")\*

3\. \*\*Context:\*\* What background details are relevant? \*(e.g., "The database table contains 10 million rows")\*

4\. \*\*Output Format:\*\* How should the response look? \*(e.g., "Provide a bulleted list followed by corrected SQL code")\*



\---



\## 2. Key Prompting Techniques



\### Zero-Shot Prompting

Directly asking the model without providing examples.

> \*\*Example:\*\*  

> "Classify the sentiment of this review: 'The server response time was terrible.' -> Sentiment:"



\### Few-Shot Prompting

Providing a few input-output examples before the actual request.

> \*\*Example:\*\*  

> "Classify sentiment:  

> Text: 'Fast database query execution.' -> Positive  

> Text: 'System crash during deployment.' -> Negative  

> Text: 'API latency increased by 200ms.' -> "



\### Chain-of-Thought (CoT)

Forcing the model to show step-by-step reasoning before giving the final answer.

> \*\*Example:\*\*  

> "Explain how to debug a 500 Internal Server Error step-by-step before summarizing the fix."



\---



\## 3. Best Practices

\- Use clear delimiters (like ` ``` ` or `---`) to separate instructions from data.

\- Specify what \*\*to do\*\* rather than what \*\*not to do\*\*.

\- Specify constraints on length, tone, and format upfront.
